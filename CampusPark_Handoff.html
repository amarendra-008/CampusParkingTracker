Project Overview

What is
CampusPark?

A cross-platform mobile app giving SDSU students real-time visibility into campus parking. Check occupancy, set smart alerts, and track sessions across all 8 structures before you even leave your dorm.

Live occupancy across 8 parking structures with zone-level status tracking
Smart alerts for availability changes, high traffic, game days, and weekly digests
Session logging to record arrival, departure, and parking duration per visit

Section 8

Tips for the Next Team

Where to start, what to expect, and how to win fast

1

Start with AsyncStorage

The #1 quick win. Add persistence in one afternoon:settings, profile, and session data should survive app restart. Use @react-native-async-storage/async-storage.

2

Mock data is well-structured

All mock arrays at the top of each screen file match a clean schema. When you connect a real API, just swap the data source:components need no changes.

3

Animations are production-ready

Don't touch the Reanimated springs unless needed. The tension:68 / friction:10 values took many iterations to feel right.

4

Backend is the critical path

Auth + real parking data are HIGH priority blockers for everything else. Consider Firebase for quick auth, or SDSU's portal API if accessible.

5

Test on real Android early

The iOS Simulator behaves differently from Android for bottom sheets and backdrop overlays. Catch the Android dropdown flicker bug before it gets worse.

6

Keep components inline (for now)

Until the app is 3–4x larger, extracting components into separate files adds overhead. Wait until real data forces you to refactor.

Section 9

Team Reflection

What we learned building CampusPark

01

What Worked Well

Expo Router's file-based routing kept navigation clean and fast. Glass morphism UI came together beautifully with just CSS. Splitting into 6 focused screen files made collaboration manageable. The Reanimated spring physics feel genuinely premium.

02

Do Differently Next Time

Plan the data layer before building UI. We built beautiful screens around mock arrays:but connecting a real API now means refactoring data flows. Also: write tests from day one, even simple smoke tests.

03

Biggest Challenge

Getting the animated bottom sheet to feel right on both iOS and Android simultaneously. The backdrop fade timing, spring physics, and safe area insets each had platform-specific quirks that took significant iteration to resolve.
